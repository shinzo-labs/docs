# Agent Runtime API

The Agent Runtime API provides internal endpoints used by agent containers to communicate with the Shinzo backend. These endpoints use agent-specific authentication tokens and are not accessible via user Platform API keys.

<Warning>
**Internal Use Only**: These endpoints are designed for agent container → backend communication. They use `agent_key` authentication instead of user API keys. External applications should use the standard [Agent API](/api/agents/overview) instead.
</Warning>

## Authentication

Agent Runtime endpoints require an agent-specific key via the `Authorization: Bearer <agent_key>` header. These keys are automatically provisioned when an agent pod starts and are different from user Platform API keys.

## Endpoint Categories

### Self-Service Endpoints

Agents use these endpoints to query their own state and configuration:

| Method | Endpoint | Description |
|--------|----------|-------------|
| `GET` | `/v1/agent-runtime/self` | Get agent's own configuration |
| `GET` | `/v1/agent-runtime/self/entities` | List available messaging entities |
| `GET` | `/v1/agent-runtime/self/mcp-servers` | List MCP servers accessible to this agent |
| `PATCH` | `/v1/agent-runtime/self/status` | Update agent execution status |
| `PATCH` | `/v1/agent-runtime/self/disk-usage` | Report disk usage statistics |
| `PATCH` | `/v1/agent-runtime/self/sdk-session` | Update SDK session metadata |

### Messaging Endpoints

Agents use these endpoints to send and receive messages:

| Method | Endpoint | Description |
|--------|----------|-------------|
| `GET` | `/v1/agent-runtime/self/messages` | List messages for this agent |
| `GET` | `/v1/agent-runtime/self/messages/pending` | Get pending messages |
| `GET` | `/v1/agent-runtime/self/messages/{id}` | Get specific message |
| `POST` | `/v1/agent-runtime/self/messages` | Send a message from agent |
| `PATCH` | `/v1/agent-runtime/self/messages/{id}` | Update message status |
| `POST` | `/v1/agent-runtime/self/messages/mark-read` | Mark messages as read |
| `POST` | `/v1/agent-runtime/self/messages/mark-delivered` | Mark messages as delivered |

### Event Subscription

| Method | Endpoint | Description |
|--------|----------|-------------|
| `GET` | `/v1/agent-runtime/subscribe` | SSE stream for real-time agent events |

## Usage Notes

- **Not for external use**: Applications integrating with Shinzo should use the standard Agent API endpoints
- **Agent harness only**: These endpoints are called by the agent SDK running inside agent containers
- **Different auth**: Uses agent keys, not user Platform API keys
- **Internal contracts**: May change without notice as they are internal infrastructure

## For External Integration

If you're building an application that needs to interact with agents, use these APIs instead:

- [Agent Management API](/api/agents/overview) - Create, configure, and manage agents
- [Agent Messaging API](/api/agents/messaging-overview) - Send messages to agents
- [Agent Filesystem API](/api/agents/filesystem-overview) - Access agent files

For real-time updates about your agents, consider using webhooks or polling the [Agent Summary](/api/agents/get-summary) endpoint.
