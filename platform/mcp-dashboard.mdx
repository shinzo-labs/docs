Once your MCP server is instrumented, the Shinzo dashboard provides powerful analytics to help you understand tool usage, optimize performance, and troubleshoot issues.

## Understanding MCP Traces

### Trace Structure

Each MCP tool execution creates a trace with the following structure:

```
Trace (Root Span)
└── Tool Execution Span
    ├── Input Processing
    ├── External API Call (if any)
    └── Response Formatting
```

### Trace Attributes

Shinzo automatically captures MCP-specific attributes:

| Attribute | Description | Example |
|-----------|-------------|---------|
| `mcp.server.name` | Name of your MCP server | `"my-mcp-server"` |
| `mcp.server.version` | Version of your MCP server | `"1.0.0"` |
| `mcp.tool.name` | Name of the tool executed | `"search_files"` |
| `mcp.tool.arguments` | Input arguments to the tool | `{"query": "auth", "path": "/src"}` |
| `mcp.tool.result` | Output from the tool | `{"files": [...]}` |
| `mcp.tool.success` | Whether the tool succeeded | `true` / `false` |
| `mcp.tool.duration_ms` | Execution time in milliseconds | `145` |
| `mcp.tool.error` | Error message (if failed) | `"File not found"` |

### Viewing Traces

1. Navigate to **Traces** in the sidebar
2. Filter by:
   - MCP server name
   - Tool name
   - Success/failure status
   - Date range
   - Duration
3. Click on any trace to see full details including:
   - Complete input arguments
   - Full output/response
   - Timing breakdown
   - Error stack traces (if applicable)

<Tip>
Use the search bar to quickly find traces by keywords in arguments or results.
</Tip>

## Debugging with Traces

### Finding Errors

1. Filter traces by `status: error`
2. Group by error message to find patterns
3. Click on a failing trace to see:
   - Input that caused the error
   - Full error message and stack trace
   - Related context from surrounding calls

### Performance Debugging

1. Sort traces by duration (slowest first)
2. Identify slow executions
3. Analyze span breakdown to see where time is spent:
   - Was it an external API call?
   - File I/O operations?
   - CPU-intensive processing?

### Example: Debugging a Slow Tool

```
Trace: search_files (2,345ms)
└── Tool Execution (2,345ms)
    ├── Parse Arguments (2ms)
    ├── File System Scan (2,300ms) ← Bottleneck!
    └── Format Response (43ms)
```

**Solution**: Implement file indexing or caching to reduce scan time.

## Token Usage Tracking

### Token Consumption by Tool

See which tools consume the most tokens:

```
Tool              Input Tokens    Output Tokens    Total Cost
──────────────────────────────────────────────────────────────
search_files            2,345           45,678    $0.73
read_file               1,234           23,456    $0.37
list_directory            890            4,567    $0.08
```

<Tip>
Token usage is tracked automatically when tools return text responses. Use this data to optimize token-heavy operations.
</Tip>

### Cost Optimization

Strategies to reduce token costs:

1. **Minimize output verbosity**: Return only necessary information
2. **Implement pagination**: For large result sets, use pagination
3. **Cache common responses**: Cache frequently-requested data
4. **Compress output**: Use abbreviations or structured formats

## Custom Dashboards

### Creating Filters

Save custom filters for quick access:

- **Production Issues**: `server:prod AND status:error`
- **Slow Queries**: `duration:>1000ms`
- **High-Value Tools**: `tool:search_files OR tool:read_file`

### Exporting Data

Export trace data for deeper analysis:

- **CSV**: For spreadsheet analysis
- **JSON**: For programmatic processing
- **API**: Query telemetry data programmatically

```bash
# Example: Export last 7 days of traces
curl -H "Authorization: Bearer YOUR_API_KEY" \
  "https://api.app.shinzo.ai/v1/telemetry/fetch?server=my-mcp-server&days=7"
```

