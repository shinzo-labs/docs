# Resources

The Resources page provides detailed insights into your MCP server infrastructure, including server metadata, resource attributes, and performance characteristics. This view helps you understand your server's capabilities and monitor its operational status.

## Overview

Resources in Shinzo Platform represent your MCP servers and their associated metadata. Each resource contains valuable information about:
- Server identification and versioning
- Environment and deployment details
- Performance characteristics
- Configuration attributes

## Resource Types

### MCP Servers
The primary resource type representing your instrumented MCP servers:
- **Service name**: Identifier for your MCP server
- **Service version**: Version information from your deployment
- **Instance ID**: Unique identifier for each server instance
- **Environment**: Development, staging, production environments

### Service Instances
Individual deployments or instances of your MCP servers:
- **Host information**: Server hostname and IP address
- **Process details**: Process ID and runtime information
- **Deployment metadata**: Version, build, and deployment time
- **Resource limits**: Memory, CPU, and other constraints

## Resource Attributes

### Standard Attributes
OpenTelemetry semantic conventions provide consistent resource attributes:

| Attribute | Description | Example |
|-----------|-------------|---------|
| `service.name` | MCP server name | `weather-mcp-server` |
| `service.version` | Server version | `1.2.3` |
| `service.instance.id` | Unique instance identifier | `weather-server-pod-abc123` |
| `deployment.environment` | Environment name | `production` |
| `host.name` | Host machine name | `server-01.example.com` |
| `process.pid` | Process identifier | `12345` |

### MCP-Specific Attributes
Custom attributes specific to MCP servers:

| Attribute | Description | Example |
|-----------|-------------|---------|
| `mcp.server.tools` | Available tools | `["get_weather", "search_locations"]` |
| `mcp.server.resources` | Available resources | `["weather_data", "location_db"]` |
| `mcp.sdk.name` | SDK used for instrumentation | `@shinzolabs/instrumentation-mcp` |
| `mcp.sdk.version` | SDK version | `1.0.8` |

### Custom Attributes
Add your own attributes for better organization:
- Team or project identifiers
- Cost center information
- Compliance tags
- Feature flags

## Resource Management

### Filtering Resources
Efficiently find resources using filters:
- **By name**: Filter by service or instance name
- **By environment**: Show only production, development, etc.
- **By version**: Filter by specific software versions
- **By status**: Active, inactive, or error states
- **By attributes**: Custom attribute-based filtering

### Sorting Options
Organize resources by various criteria:
- **Alphabetical**: Service name A-Z or Z-A
- **Recently active**: Most recently seen first
- **Version**: Newest or oldest versions first
- **Error count**: Resources with most/least errors

### Search Functionality
Quickly locate specific resources:
- Full-text search across all attributes
- Regex pattern matching
- Wildcard searches (`weather-*`)
- Attribute-specific searches (`service.name:weather`)

## Resource Details

### Server Information
Detailed view of each resource includes:
- Complete attribute list
- Recent activity summary
- Associated traces and spans
- Performance metrics

### Health Status
Monitor resource health with status indicators:
- 🟢 **Healthy**: Receiving telemetry data regularly
- 🟡 **Warning**: Intermittent data or performance issues
- 🔴 **Critical**: No recent data or high error rates
- 🔘 **Unknown**: Insufficient data for status determination

### Activity Timeline
Track resource activity over time:
- First seen timestamp
- Last active timestamp
- Data collection periods
- Gaps in telemetry data

## Performance Insights

### Resource Utilization
Monitor how your MCP servers are performing:
- **Request volume**: Number of tool calls and resource accesses
- **Response times**: Average, P50, P95, P99 latencies
- **Error rates**: Failed operations over time
- **Throughput**: Operations per second/minute

### Capacity Planning
Use resource data for planning:
- Historical usage patterns
- Growth trends over time
- Peak usage periods
- Resource constraint identification

## Best Practices

### Resource Naming
Consistent naming helps with organization:
- Use descriptive, hierarchical names
- Include environment in the name if needed
- Follow your team's naming conventions
- Avoid special characters that complicate filtering

### Attribute Management
Effective use of resource attributes:
- Add relevant custom attributes
- Use consistent attribute names across services
- Include version and environment information
- Tag resources for cost allocation or compliance

### Monitoring Strategy
Develop a resource monitoring approach:
- Set up alerts for resource health changes
- Monitor resource count for capacity planning
- Track attribute changes for compliance
- Review inactive resources regularly

## Troubleshooting

### Missing Resources
If expected resources don't appear:
1. Verify SDK instrumentation is properly configured
2. Check ingest token permissions
3. Confirm telemetry data is being sent
4. Review time range settings

### Incorrect Attributes
To fix resource attribute issues:
1. Update instrumentation configuration
2. Restart MCP server to apply changes
3. Allow time for new data to appear
4. Use custom processors to modify attributes
